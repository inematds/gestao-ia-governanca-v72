Lesson 2 · 18 min

Permissions, identity and log

In G3 you decided the color of each action, and in G4 you contracted each tool with minimum access. What's left is to check that this really exists and keeps existing. At Horizonte, the log of actions was turned off "to save space" and the email assistant was approved with a "go ahead" on WhatsApp. This lesson gives the manager a 10-item checklist to review every month.

Start the lesson

In this lesson you will

  1. 1Why the agent needs its own identity
  2. 2Grant permission in writing, with scope and expiration
  3. 3The log that answers the five questions
  4. 4The monthly access review and the agent's off switch

Goal: make sure each agent action has its own identity, a permission granted in writing, and a log that says who, when, what and with which version.

01 · Four checks for the manager

You don't configure anything: you check that it exists and ask for what's missing. Click each step.

02 · What each check asks for

Four lab problems, seen from the side of the person accountable for the area.

1. Own identity

If Hora acted with Patrícia's login, the log would say it was Patrícia, and turning off Hora would mean locking out Patrícia. Ask for an account in the agent's name in every system it uses.

The credential for that account stays on the server, kept by IT. You don't need to see it: you need to know who has access to it and when it was last changed.

In the labThe email assistant's configuration carries the token inside the file itself. Patrícia's request to Rafael: token in a server vault, with the list of who has access.

2. Permission granted, not inherited

The email assistant was given read, send, delete and empty the trash, all approved in one go, because Carlos replied "go ahead and turn it on" on WhatsApp. Nobody requested each permission or said how long it was valid.

A grant has a request, a scope, an approver and an expiration. Whoever requests it doesn't grant it alone, and whoever configures it doesn't decide what is allowed.

At HorizonteRequest #3: email assistant reads comercial@ and prepares replies. Scope: only that mailbox. Approves: Patrícia. Valid for: 90 days. Send: with approval for each email. Delete: not allowed.

3. The log of the five questions

Hora had the log turned off "to save database space". When finance asked who approved the Hotel order, nobody knew. A log is what turns "I think it was" into "this is how it happened".

One line per action: who and which version, when, what, how much, who approved. Stored in a place the agent and the operator can't edit, for as long as the company decides.

Log lineHora v2.0 · 16:44 · created order for Hotel Fazenda Recanto · R$ 28,120 list price, no discount · approved by Patrícia at 17:02, exact order · conversation c-202.

4. Review and turn off

Once a month, compare each agent's access list with the matrix. Access that is left over gets removed. Along with that, check a sample of the log and test the off switch.

Okta (AI Agents at Work 2026, a survey by an identity vendor that sells the solution) treats agent identity as a topic of its own and reports weaker controls for agents than for employees in almost two thirds of organizations.

ShutdownAn agent that is retired has its credentials revoked the same day, like an employee who leaves. The log is kept.

Also in the lab: the model version is set as "modelo-exemplo", with no number. Without a version, the log doesn't say which Hora did what.

  • Ticking "yes" from memory. Each "yes" points to where you can see it: the file field, the screen or the person who confirmed.
  • Log without a version. Without the agent's version, you can't tell whether the error comes from the new version or the old one.
  • A log the agent edits. If whoever is being logged can delete the line, it proves nothing.
  • Review without a date. "Let's take a look" is not a review: put it on the calendar.
  • Shutdown never tested. You only find out the button doesn't work on the day you need it.

04 · Practice

The Hora checklist uses the lab files; the one for your agent uses yours.

1 · The Hora and assistant checklist

30 min

Open the Hora configuration and the email assistant configuration in the lab. Apply the checklist to both, marking where each answer shows up. Then write the log line that should exist for the hotel order (conversation c-202), with Patrícia's approval.

Done when: both checklists have all 10 items answered yes or no, with the file field that shows each answer; every "no" has an owner and a deadline; and the log line for the hotel order answers the 5 questions, with the Hora version.

2 · Your agent's checklist

40 min

Ask IT (or the vendor) for the configuration of the agent you chose in lesson 1 and the list of who has access to the credentials. Apply the checklist, run the check prompt, and put the first monthly access review on the calendar, with the off switch test.

Done when: your agent's checklist is saved with all 10 items and the evidence for each; every "no" has an owner and a deadline; and the monthly review is on the calendar with a date, attendees, and the off switch test.

Lab pieces: Hora configuration and email assistant. Technical risks and LGPD: risks lesson and data and LGPD lesson from Profissional 2030 Base.
